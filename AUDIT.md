## Как проверял

- **Чтение кода.** Прочитаны `stock-worker.js` и `sw.js` целиком и весь скрипт `index.html`. Из словарей переводов прочитаны только места, где они используются; сами словари проверены скриптом на пропущенные ключи.
- **Стенд в браузере.** Headless Chromium (Playwright) открывал приложение с `localhost`. **Все внешние запросы обрывались ещё до отправки**: Google, воркер, monobank, биржи, курсы валют. Где нужен был ответ сервера, его подменяла заглушка (курсы monobank, кэш биржи). Данные подкладывались в `localStorage` или шли через собственные функции импорта приложения. Для замера производительности включалось 6-кратное замедление CPU (CDP `Emulation.setCPUThrottlingRate`).
- **Воркер локально.** `stock-worker.js` запускался в Node 22. KV и Cache API заменены заглушками в памяти, Anthropic — заглушкой. Ничего не деплоилось, реальных запросов к Cloudflare и Anthropic не было.
- **Уверенность.** «Подтверждено (тест)» — воспроизведено на стенде. «Подтверждено (код)» — следует из кода однозначно, но отдельно не запускалось. «Возможно» — нужна проверка на живом окружении.

Намеренные решения в находки не попали: `TRIAL_FROZEN = true`, бесплатный владелец (`ADMIN_SUB`), ключи бирж и токен monobank только на устройстве, прямой вызов monobank с телефона, лимит ИИ 3 запроса в сутки. Русский язык админ-панели — тоже осознанный выбор (комментарий в коде), его в переводы не включал.

## Критично

### 1. Лимиты ИИ и общий потолок расходов обходятся параллельными запросами

- **Уровень:** критично.
- **Где:** `stock-worker.js:356-371` (`isRateLimited`), `382-405` (`readCount`/`reserveCount`), `1097-1124` (`handleAI`); вызов IP-лимита — `287-292`.
- **Сценарий.** Любой человек входит через Google и одновременно отправляет N запросов на `/ai`. Все N читают `user:…` и `global:…` раньше, чем кто-то из них успел записать резерв. Все видят 0, все проходят проверку, все записывают 1.
  - IP-лимит (`AI_IP_PER_MIN = 10`) держится на Cache API. Воркер работает на `plain-bread-df6d.mnacik1988.workers.dev`, а [по документации Cloudflare](https://developers.cloudflare.com/workers/runtime-apis/cache/) Cache API на `*.workers.dev` ничего не делает. Даже на своём домене схема «прочитал → записал» не атомарна.
  - На стенде 30 одновременных запросов одного пользователя дали **30 вызовов Claude**, а счётчики после этого: `user = 1`, `global = 1`. Результат тот же и с работающей заглушкой Cache API.
  - Итог: дневной лимит одного человека не соблюдается, а **общий потолок в 100 запросов — «главный предохранитель расходов» — тоже**. Пачка по 1000 запросов раз в минуту даёт расход без верхней границы. Заодно сжигается дневной потолок для всех остальных.
  - В комментарии к `reserveCount` гонка упомянута как «пара лишних запросов». На деле проходит вся параллельная пачка целиком.
- **Как исправить.** Нужен атомарный счётчик.
  - Вариант без новых платных ресурсов: D1 уже подключена, а в SQLite одна запись атомарна. Строка на пользователя и день плюс строка `global` за день, условное увеличение одним запросом: `UPDATE … SET n = n + 1 WHERE key = ? AND n < ? RETURNING n`. Нет строки в ответе — отказ. Откат делать через `n = n - 1`.
  - Для частоты с IP и с аккаунта — встроенный Rate Limiting binding Cloudflare вместо Cache API.
  - Дополнительно: не больше одного одновременного запроса на пользователя.

### 2. Сохранённый XSS через имя кредита в бэкапе

- **Уровень:** критично. Условие — человек импортирует присланный ему файл и нажимает кнопку частичного погашения.
- **Где:** `index.html:10913`. Имя кредита подставляется прямо в строку JS внутри атрибута `onclick="openPartialPayModal(…)"`. Санитайзер — `index.html:8705` (`neutralizeText`).
- **Сценарий.**
  - `neutralizeText` заменяет только `< > " \``, а символы `&` и `'` пропускает.
  - Шаблон убирает буквальные кавычки, но не HTML-сущности. Браузер раскодирует сущность уже внутри атрибута, и текст из бэкапа выходит за пределы строки JS.
  - На стенде импорт такого файла прошёл проверку. После нажатия «+ Часткове погашення» подставленный код выполнился и смог прочитать `localStorage`: там лежат токен monobank, ключи бирж и сессия.
  - Комментарий у санитайзера (`8687-8696`) обещает, что из текста «ни тег, ни атрибут уже не собрать». Для JS внутри атрибута это не так.
  - Другие обработчики я проверил поиском: подставляют только id и константы. Это место единственное.
- **Как исправить.**
  - Не подставлять текст в inline-обработчики. Передавать только `l.id`, а имя брать из `liabilities` внутри `openPartialPayModal`. Либо вешать обработчик через `addEventListener`.
  - Дополнительно: в `neutralizeText` заменять ещё `&` и `'`.
  - Правило на будущее: внутри `on…="…"` не должно быть ничего, кроме id из `isSafeDataId`. `escHtml`/`escAttr` там не защищают: сущность раскодируется раньше, чем выполнится JS.
- **Уверенность:** подтверждено (тест).

### 3. Продажа акций добавляет в капитал сумму в 41 раз больше

- **Уровень:** критично.
- **Где:** `index.html:8023-8024` — валюта продажи по умолчанию равна `getStockCashCurrency(sec)`. `8054-8055` — поле цены подписано «(₴)» и заполнено ценой в гривнах. `8065-8083` — `addStockSaleCash(sec, qty*price, saleCurrency)`.
- **Сценарий.**
  - В разделе «Акції» у «Кошти від продажів» выбрана валюта USD — естественный выбор для американских бумаг.
  - Открываем AAPL и продаём 10 шт. Цена в форме подставлена «9 000», это гривны, валюта продажи — USD.
  - На стенде в кэш раздела записалось **90 000 USD ≈ 3 735 000 ₴** вместо 90 000 ₴. Окно подтверждения при этом пишет «по $9 000», то есть сумма уже выглядит долларовой.
  - То же самое случается при кэше в UAH, если сменить валюту в выпадающем списке.
- **Как исправить.** Пересчитывать цену при смене валюты продажи: `price / getStockCurrencyRate(saleCurrency)`. Либо хранить и показывать цену в выбранной валюте, а подпись «(₴)» менять вместе с ней.
- **Уверенность:** подтверждено (тест).

## Важно

### 4. Откат резерва затирает чужие списания

- **Где:** `stock-worker.js:407-412` (`releaseCount` пишет `prevValue`), `1126-1129`.
- **Сценарий.**
  - Запрос A прочитал `global = 0` и записал 1, потом ждёт Claude несколько секунд.
  - За это время ещё 4 пользователя успешно подняли счётчик до 5.
  - Claude вернул A ошибку (529), и откат записал 0. На стенде после 4 успешных и одного неудачного запроса `global = 0` при ожидаемых 4.
  - Каждая ошибка Claude обнуляет учёт за время своего ожидания, и потолок расходов «течёт».
- **Как исправить.** Атомарное уменьшение на 1 (см. п. 1), а не запись старого значения.
- **Уверенность:** подтверждено (тест).

### 5. Открытые эндпоинты котировок без реальной защиты

- **Где:** `stock-worker.js:266-269` (проверка `Origin`), `313-317` (IP-лимит на Cache API), `459-474` (`/multi`), `558-586` (`/news`).
- **Сценарий.**
  - Заголовок `Origin` подделывается любым скриптом не из браузера, а IP-лимит на `workers.dev` не работает (см. п. 1).
  - Если слать `/multi?tickers=` со случайными несуществующими тикерами, каждый новый тикер — отдельный вызов Finnhub, кэш в памяти не помогает.
  - Лимит бесплатного Finnhub — 60 в минуту, он выбирается быстро. После этого котировки ломаются у всех пользователей (429).
- **Как исправить.** Rate Limiting binding вместо Cache API. Требовать сессию для `/multi`, `/price`, `/news`. Кэшировать и ответ «Ticker not found».
- **Уверенность:** подтверждено (код + документация Cloudflare). Сама выработка лимита Finnhub не воспроизводилась.

### 6. Курс USDT/₴ замерзает после первого обновления

- **Где:** `index.html:5061-5067` — поле `usdtUah` обновляется, только пока в нём `''` или `'41'`. `6306` — `getCryptoRate()` берёт сначала `usdtUah`.
- **Сценарий.**
  - Первое получение курса записало в поле 41.50 и сохранило его.
  - Курс сменился на 44.00: `liveRates.USD = 44`, а `usdtUah` остался 41.50 и после перезапуска тоже.
  - На стенде $10 000 на бирже дали 415 000 ₴ вместо 440 000 ₴. Акции в USD при этом считаются по живому курсу, то есть внутри одного итога два разных курса.
- **Как исправить.** Хранить признак «курс задан вручную» (`setCustomUsdtRate`). Без этого признака всегда брать `liveRates.USD`.
- **Уверенность:** подтверждено (тест).

### 7. Металлы оцениваются по константам

- **Где:** `index.html:9873` (`metalPrices` нигде не обновляется), `9875` (`METAL_FALLBACK`), `9948-9957`.
- **Сценарий.**
  - 10 г золота, купленные по 5 000 ₴/г, оцениваются в 3 977 ₴/г: это $97 × курс, а $97 — константа.
  - Строка «Зараз» и P&L показывают выдуманную цену.
  - Цена покупки как запасной вариант никогда не срабатывает: константа всегда больше 0.
- **Как исправить.** Подключить источник цены, например через воркер. До этого брать цену покупки или явно помечать оценку как ручную.
- **Уверенность:** подтверждено (тест).

### 8. `parseFloat` вместо `parseInputNumber` в суммах разделов

### 9. Битые или чужие данные из бэкапа ломают запуск

- **Где:** `index.html:10001` (`byType[it.type]` для неизвестного типа металла), `10651` (`pp.date` при `null`), `14078` (валидатор проверяет `partialPays`, а поле называется `partialPayments`). Всё это внутри одного `try` в `bootstrapApp` (`8939-8998`).
- **Сценарий.**

  - Встроенного способа откатиться нет (п. 12).
- **Как исправить.**
  - Проверять `metalsSections[].items[].type` по списку разрешённых типов.
  - Исправить имя поля в валидаторе на `partialPayments`.
  - В рендерах пропускать неизвестные значения вместо падения.
  - Разбить `bootstrapApp` на независимые `try`.
- **Уверенность:** подтверждено (тест).

### 10. Контекст для ИИ с неверными суммами

- **Где:** `index.html:12202-12227`, `12297-12304`.
- **Сценарий.**
  - Отображение в USD: суммы в гривнах подписываются символом «$». На стенде шапка показывала «110 000 $», а ИИ получил «Загальний капітал: 415 000 $».

  - Удалённые (скрытые) разделы акций тоже попадают в контекст.

### 11. Тяжёлые перерисовки на слабом телефоне

### 12. Резервные копии на устройстве не защищают

- **Где:** `8537-8545` (`savedAt` в каждой записи), `8798-8808`, `13975-13998`.
- **Сценарий.**
  - Каждое сохранение отличается от предыдущего хотя бы `savedAt`, поэтому `kapital_v6_prev` всегда равен прошлому сохранению, сделанному секунды назад. На стенде после правки и двух сохранений `prev` уже совпадал с основной копией.

  - Зато эта копия удваивает занятое место в `localStorage`.
- **Как исправить.** Сравнивать данные без `savedAt` и ротировать `prev`, скажем, не чаще раза в сутки. Добавить кнопку «Відкотити імпорт».
